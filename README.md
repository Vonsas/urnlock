# Urnlock

Valve 게임 Deadlock 정보 사이트. 영웅, 아이템, 티어, 통계, 빌드, 전적 검색을 한국어, 영어, 중국어(간체)로 보여 준다.
혼자 만들고 운영하는 비상업 팬 사이트이고 Valve 와는 관계없다.

https://www.urnlock.com

이 저장소는 포트폴리오용 공개 사본이다. 평소 개발은 비공개 저장소에서 이슈, 브랜치, PR, 리뷰를 거쳐 하고,
여기에는 코드를 정리해 한 커밋씩 옮긴다 (마지막 반영 2026-11-09). 빠진 것은 맨 아래에 적었다.

## 기능

- 티어와 통계: 랭크별, 기간별 승률을 빌드할 때 받아 티어 보드와 승률표를 만든다. 승률만 보면 쉬운 영웅이 위로 올라오는 문제가 있어서
  그 영웅을 오래 해 본 사람들의 승률을 따로 본다.
- 영웅 상세: 능력과 스탯(영웅 간 순위), 승률 추이, 랭크별 / 경기 길이별 승률, 라인전, 스킬 선마, 추천 빌드.
- 아이템: 게임 상점 화면을 본뜬 목록과 게임 툴팁 구성을 따른 상세 창. 많이 산 영웅 3명, 평균 구매 시각, 되판 비율을 보여 주는 통계 탭.
- 빌드: 전 영웅의 추천 빌드를 카드로 모아 작성자, 영웅, 판수, 승률로 거른다. 작성자가 아이템에 남긴 설명도 보여 준다.
- 전적 검색: 브라우저에서 API 를 바로 불러 플레이어와 매치 기록을 그린다. 매치 펼쳐 보기, 팀 소울 차이 그래프.
- 순위표: 지역별 100위와 영웅별 순위표. Valve 순위표는 이름만 주기 때문에, 같은 이름의 계정 후보 중 실제 계정을 랭크 기록과 스팀 이름으로 가려서 프로필 사진, 티어, 주 영웅을 붙인다.
- 패치노트: Steam 공지를 구역별로 나누고, 영웅 변경은 능력별로 묶어 두 단으로 보여 준다. 줄 단위 번역 사전으로 한국어와 중국어를 내고, 숫자와 공식 용어가 원문과 맞는지 빌드 때 검사한다.
- 유저 가이드와 한 줄 팁: 영웅 가이드와 게임 가이드로 나뉜다. 스팀 로그인으로 글쓰기, 추천, 신고, 사진 올리기. 욕설 검사와 운영자 화면이 있다.
- 색 테마 6개: 색은 전부 토큰으로 관리해서 방문자가 바꿀 수 있다.

## 기술

- Astro 7 정적 출력, Tailwind CSS 4, TypeScript(strict), pnpm. UI 라이브러리는 쓰지 않고 컴포넌트를 직접 만들었다.
- 브라우저 스크립트는 프레임워크 없이 TypeScript 로만 짰다 (`src/scripts/`). 외부에서 온 문자열은 `textContent` 로만 넣는다.
- 화면은 Cloudflare Pages, 서버는 Vercel 함수(`api/`), 저장소는 Upstash Redis, 사진은 Cloudflare R2. R2 는 패키지 없이 fetch 와 Web Crypto 로 요청에 서명한다.
- Vercel 무료 CDN 한도에 닿은 뒤로 정적 파일은 Cloudflare 에서 내보내고 `/api` 만 Pages 함수로 프록시해 넘긴다 (`functions/api/[[path]].js`). Vercel CDN 요청이 하루 약 3.9만 건에서 약 250건으로 줄었다. 프록시 헤더는 비밀값이 맞을 때만 믿고, 공개 GET 은 Cloudflare 엣지에 60초 캐시한다.
  무료 요금제의 함수 개수 제한(12개)은 빌드와 PR 마다 검사한다.
- 6시간마다 데이터를 새로 받아 다시 배포한다. GitHub 예약 실행이 몇 시간씩 밀려서 Cloudflare Worker 가 대신 깨우고, GitHub 예약은 예비로 둔다 (`workers/rebuild-trigger`). 빌드 중에 티어 데이터를 검사해서 이상하면 배포를 멈추고 이전 배포를 그대로 둔다.
- 같은 Worker 가 2분마다 새 Steam 패치 글을 살핀다. 새 패치로 시작한 배포는 나머지 데이터를 캐시로 재사용해 빌드 시간을 줄인다.
- CSP 등 보안 헤더, 서명 쿠키, 같은 사이트 요청만 받기, 요청 수 제한, 스팀 로그인 응답 재확인. 운영자 화면은 Cloudflare Access 와 비밀번호 두 겹이고, 함수에서도 Access 토큰(RS256)을 직접 검증한다 (`api/_lib/access.ts`).

## 작업 방식

Claude Code 를 쓰면서 만들었다. 정한 것과 그 이유는 `CLAUDE.md` 에 계속 적어 두고, `.claude/agents/` 에 이슈 정리, 구현, 리뷰용 에이전트를 나눠 두었다.
리뷰에서 고칠 것이 없어질 때까지 고치고 다시 리뷰한 뒤 머지한다. 운영하면서 쓴 문서는 `docs/` 에 있다 (배포 실패 기록, 무료 한도 대응, 요청 수 제한, DNS 이전, 정적 파일과 API 분리 설계, 재빌드 깨우기).

## 실행

Node.js 22.12 이상, pnpm 이 필요하다.

```sh
pnpm install
pnpm dev      # http://localhost:4321
pnpm check    # 타입 검사
pnpm build    # dist/
```

데이터는 빌드할 때 deadlock-api.com 에서 받는다. 못 받으면 `.cache/api/` 캐시를, 그것도 없으면 목업 데이터를 쓴다.
가이드, 팁, 로그인(`api/`)은 Vercel 환경 변수가 있어야 돌아가고 이 사본에는 그 값이 없다.

## 이 사본에서 뺀 것

- 티어 점수 공식. `src/data/api/tier-score.ts` 는 입력과 출력 모양만 같은 단순한 버전이라, 이 사본으로 빌드한 티어는 사이트와 다르다.
- 커밋 기록. 비공개 저장소의 약 700개 커밋과 100여 개의 PR, 리뷰 대신 코드만 옮겼다.
- 계정 이름, 비밀값, 방화벽 수치, 보안 설정 세부처럼 운영에만 필요한 값.
